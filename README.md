# ระบบจองทรัพยากรสำนักงานเกษตร

ต้นแบบระบบจองห้องประชุมและรถสำนักงาน พัฒนาด้วย Next.js App Router, TypeScript,
Mongoose และ MongoDB

## เริ่มต้นใช้งาน

1. ติดตั้งแพ็กเกจด้วย `npm install`
2. เปิด MongoDB ในเครื่องด้วย `docker compose up -d` (หรือใช้ MongoDB Atlas แล้วใส่ connection string ใน `MONGODB_URI`)
3. คัดลอก `.env.example` เป็น `.env.local` แล้วตั้งค่า `MONGODB_URI`, `SESSION_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`
4. รัน `npm run seed` เพื่อสร้างห้อง/รถตัวอย่าง ดัชนี และผู้ดูแลระบบคนแรก (ระบบจะ seed ให้เองตอนเรียก API ครั้งแรกด้วย)
5. รัน `npm run dev` แล้วเปิด `http://localhost:3000` เข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบ

> หากใช้ MongoDB Atlas แล้วพบ `querySrv ECONNREFUSED` ให้กำหนด `MONGODB_DNS_SERVERS=8.8.8.8,8.8.4.4`
> ใน `.env.local` แล้วเริ่ม `npm run dev` ใหม่ เพื่อให้ Node.js ใช้ DNS server ที่ระบุสำหรับการค้นหา SRV

> โหมดพัฒนา (ไม่ใช่ production) ถ้าไม่ตั้ง `ADMIN_*` จะสร้างบัญชี `admin` / `admin1234` ให้ — ต้องเปลี่ยนรหัสผ่านทันที
> โหมด production ต้องตั้ง `SESSION_SECRET` (อย่างน้อย 16 ตัวอักษร) และ `ADMIN_PASSWORD` (อย่างน้อย 8 ตัวอักษร)

## ระบบผู้ใช้และสิทธิ์

- เข้าสู่ระบบด้วยชื่อผู้ใช้/รหัสผ่าน (เก็บแบบ scrypt) session เป็นคุกกี้ `httpOnly` ที่เซ็นด้วย HMAC อายุ 12 ชม.
  เปลี่ยนรหัสผ่านแล้ว session เดิมจะหมดอายุ และมีการจำกัดความถี่เมื่อรหัสผ่านผิดซ้ำ
- ชื่อผู้จอง/ผู้ขอใช้รถมาจากบัญชีที่ล็อกอิน ไม่ใช่ช่องพิมพ์อิสระ
- ผู้ใช้ทั่วไป: จอง/แก้ไข/ยกเลิกห้อง**ของตัวเอง**, บันทึกการใช้รถและขากลับ**ของตัวเอง**
- ผู้ดูแลระบบ: จัดการการจองและขากลับของทุกคน, เพิ่ม/แก้ไข/ปิดใช้งานห้อง รถ และผู้ใช้ (เมนู "จัดการระบบ")

## โครงสร้างข้อมูล

- `User`: `username`, `displayName`, `department`, `role` (`admin`/`user`), `passwordHash`, `active`
- `MeetingRoom`: ตัวระบุ `code`, ชื่อ, จำนวนที่นั่ง, ที่ตั้ง, สิ่งอำนวยความสะดวก และสถานะใช้งาน
- `MeetingRoomBooking`: `roomCode`, `startAt`, `endAt`, `topic`, `attendees`, `requester`/`requesterId`,
  `department`, `phone`, `status` (`confirmed`/`cancelled`)
- `OfficeVehicle`: ตัวระบุ `code`, ชื่อ, ทะเบียน, จำนวนที่นั่ง, ประเภท และสถานะใช้งาน
- `VehicleBooking`: `departureLog` (ปลายทาง วัตถุประสงค์ ผู้โดยสาร เวลาที่คาดว่าจะกลับ ฯลฯ) และ `returnLog`
  (เลขไมล์สิ้นสุด เติมน้ำมัน) พร้อม `totalDistance` (กม.)
- ข้อมูลห้อง/รถตั้งต้นอยู่ที่ `lib/default-catalog.ts` แห่งเดียว (ใช้ทั้ง seed และข้อมูลตัวอย่างฝั่งหน้าจอ)

## API

ทุก endpoint (ยกเว้น `login`) ต้องล็อกอิน

| Method | Endpoint | การทำงาน |
| --- | --- | --- |
| `POST` | `/api/auth/login`, `/api/auth/logout`, `/api/auth/password` | เข้า/ออกจากระบบ, เปลี่ยนรหัสผ่าน |
| `GET` | `/api/auth/me` | ผู้ใช้ปัจจุบัน |
| `GET` | `/api/catalog` | ห้อง/รถ (รถมี `lastOdometer` จากทริปล่าสุด; แอดมินใช้ `?all=1` ดูรายการที่ปิดใช้งาน) |
| `GET`, `POST` | `/api/meeting-bookings` | รายการจอง (ย้อนหลัง 30 วัน) / จองห้อง |
| `PATCH` | `/api/meeting-bookings/:id` | แก้ไขการจอง หรือ `{ "action": "cancel" }` ยกเลิก (เจ้าของ/แอดมิน) |
| `GET`, `POST` | `/api/vehicle-bookings` | ภาพรวม (รถที่ยังไม่คืน + 20 ล่าสุด + จำนวนทั้งหมด) / บันทึกก่อนออกเดินทาง |
| `PATCH` | `/api/vehicle-bookings/:id/return` | บันทึกขากลับ เลขไมล์สิ้นสุด น้ำมัน (ผู้บันทึก/แอดมิน) |
| `GET` | `/api/vehicle-bookings/logbook` | สมุดเดินทางแบบกรอง (`status`, `from`, `to`, `q`, `vehicleCode`) และแบ่งหน้า (`page`, `limit`) |
| `GET` | `/api/vehicle-bookings/export` | ส่งออก CSV ตามตัวกรองเดียวกัน (สูงสุด 5,000 แถว) |
| `GET` | `/api/vehicle-bookings/summary?month=YYYY-MM` | สรุปกิโลเมตร/น้ำมันรายเดือนต่อคัน (เวลาประเทศไทย) |
| `POST`, `PATCH` | `/api/admin/catalog/{rooms,vehicles}[/:code]` | เพิ่ม/แก้ไข/เปิด-ปิดใช้งานห้องและรถ (แอดมิน) |
| `GET`, `POST`, `PATCH` | `/api/admin/users[/:id]` | จัดการผู้ใช้ (แอดมิน) |

## ฟีเจอร์หน้าจอ

- **ปฏิทินห้องประชุม** รายวัน (แยกตามห้อง) / รายสัปดาห์ (ห้องเดียว) คลิกช่องว่างเพื่อเติมห้อง/เวลาลงฟอร์ม
  คลิกรายการที่จองแล้วเพื่อดูรายละเอียด แก้ไข หรือยกเลิก ฟอร์มเตือนทันทีถ้าเวลาชนกัน
- **ค่าเริ่มต้นฟอร์ม** เริ่ม = เวลาปัจจุบัน, สิ้นสุด = +1 ชม., ผู้เข้าร่วมจำกัดตามความจุห้อง,
  เลขไมล์เริ่มต้นดึงจากทริปล่าสุดของรถ (เตือนถ้าต่ำกว่า), ผู้โดยสารจำกัดตามจำนวนที่นั่ง
- **รีเฟรชอัตโนมัติ** ทุก 1 นาที และเมื่อกลับมาที่แท็บ นาฬิกา/สถานะว่าง-ใช้งานอัปเดตตาม
- **เตือนรถไม่คืน** ใช้เวลา "คาดว่าจะกลับ" ที่กรอกไว้ ถ้าไม่กรอกใช้เวลาออก + 10 ชม. (แก้ที่ `OVERDUE_FALLBACK_HOURS` ใน `components/dashboard/utils.ts`)
- **เมนู "บันทึกการใช้รถ"** (เปลี่ยนจาก "จองรถ") เพราะระบบบันทึกตอนนำรถออกจริง ไม่ได้จองล่วงหน้า
  หากอนาคตต้องการจองล่วงหน้าจริง ต้องเพิ่มสถานะ `reserved` และตรวจช่วงเวลาซ้อนของรถ
- โหมดออฟไลน์ปิดปุ่มบันทึกทุกฟอร์ม, มี skeleton ตอนโหลด, modal มี focus trap และเมนูมี `aria-current`

## ขั้นตอนลงบันทึกการใช้รถ

1. **ก่อนออกเดินทาง:** เลือกรถ (เลขไมล์เริ่มต้นเติมให้จากทริปล่าสุด) ระบุปลายทาง วัตถุประสงค์ พนักงานขับรถ ผู้โดยสาร
2. **เมื่อกลับถึงสำนักงาน:** เปิดสมุดบันทึก เลือกรายการที่กำลังเดินทาง บันทึกวันเวลากลับ เลขไมล์สิ้นสุด และน้ำมัน (ถ้ามี)
3. ระบบตรวจว่าเวลาและเลขไมล์ไม่ย้อนก่อนค่าเริ่มต้น แล้วคำนวณระยะทางรวมเป็นกิโลเมตร

## การป้องกันการจองซ้ำ

- รถ: partial unique index ใน MongoDB ทำให้รถ 1 คันมีรายการ `in_use` ได้เพียงรายการเดียว (atomic)
- ห้องประชุม: ตรวจเวลาซ้อนก่อนบันทึก และตรวจซ้ำหลังบันทึก (ทั้งตอนจองและตอนแก้ไข) หากชนพร้อมกัน
  รายการที่ตามหลังจะถูกถอนหรือคืนค่าเดิม (หากมีผู้ใช้จำนวนมากควรใช้ transaction หรือ lock ระดับห้อง)

ตรวจชนิดข้อมูลด้วย `npm run typecheck` และตรวจโค้ดด้วย `npm run lint`

## ยังไม่ได้ทำ

- แจ้งเตือนผ่าน LINE/อีเมล (ปุ่มกระดิ่งและกล่อง "ต้องการความช่วยเหลือ?" ที่ไม่มีหน้าที่ถูกนำออกแล้ว)
  หากจะทำ LINE ให้ใช้ LINE Messaging API เพราะ LINE Notify เลิกให้บริการแล้ว
- จองรถล่วงหน้า (ดูหมายเหตุด้านบน)

- `app/booking-dashboard.tsx`: เช็กการล็อกอินและเลือกหน้าที่แสดง
- `components/dashboard/`: shell, ล็อกอิน, ภาพรวม, ปฏิทิน+ฟอร์มจองห้อง, ฟอร์มบันทึกการใช้รถ, สมุดเดินทาง, จัดการระบบ

- `lib/session.ts`, `lib/password.ts`: ระบบล็อกอิน · `lib/booking-api.ts`: API client · `lib/default-catalog.ts`: ข้อมูลตั้งต้น
- `scripts/seed.ts`: `npm run seed`
